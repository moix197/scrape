## Scope

Wix and similar builders put the real brand colours and fonts in runtime CSS the static scan (`site-colors.json`, `fonts.json`) never sees. Sample `getComputedStyle` on each page rendered by C07 — during the DESKTOP visit, one page load, no extra request — and write a new file with per-page samples plus a site-level aggregate.

Output `output/<domain>/computed-style.json` (verbatim shape):

```json
{
  "pages": [
    { "url": "...", "slug": "home", "samples": [
      { "selector": "body", "fontFamily": "...", "color": "rgb(17, 17, 17)", "backgroundColor": "rgb(255, 255, 255)", "fontWeight": "400" }
    ] }
  ],
  "site": {
    "fonts":  [ { "family": "Playfair Display", "weight": "700", "roles": ["h1", "h2"] } ],
    "colors": [ { "hex": "#ff0050", "score": 10, "roles": ["button|.btn|[role=button]"] } ]
  }
}
```

Selectors sampled, in this order, with these exact `selector` keys: `body`, `h1`, `h2`, `p`, `a`, `button|.btn|[role=button]` (DOM query `button, .btn, [role=button]`), `nav`, `header`, `footer`. For each key take the FIRST VISIBLE match (`el.getClientRects().length > 0` and computed `visibility !== 'hidden'`); no visible match means no sample for that key. Values are the raw `getComputedStyle` strings for `fontFamily`, `color`, `backgroundColor`, `fontWeight`.

Aggregate (`site`):

- `colors`: for every sample, both `color` and `backgroundColor` are normalised rgb/rgba to `#rrggbb` via colors.js `normalizeColorValue` (returns `null` for `transparent`, `rgba(0,0,0,0)`, alpha < 0.15 — those are ignored). Each hex is scored with `weightForSelector(selector)` from colors.js (button|.btn = 5, nav|header = 4, a = 4, body = 3, footer = 2, default 1 — so h1/h2/p score 1), summed across all pages and samples; `roles` = unique selector keys that produced that hex; sorted by `score` desc; capped at 8 (same limit as `scoreSiteColors`).
- `fonts`: `family` = first family of `fontFamily` with surrounding quotes stripped and trimmed; `weight` = `fontWeight`; one entry per `(family, weight)`; `roles` = unique selector keys; sorted by `roles.length` desc.

`site-colors.json`, `fonts.json`, `palette.json` are untouched — this is an additional signal, not a replacement.

Implementation:

- `src/extract/colors.js` — add `export` to `normalizeColorValue` (L45) and `weightForSelector` (L80). Nothing else changes.
- `src/render/computedStyle.js` (new):
  - `export const STYLE_SELECTORS = [{ key: 'body', query: 'body' }, ..., { key: 'button|.btn|[role=button]', query: 'button, .btn, [role=button]' }, ...]` in the order above.
  - Pure DOM-reading helpers that take `(document, getComputedStyle)` as arguments so they run in node against fakes: `pickVisibleMatch(document, getComputedStyle, query)` and `readSample(getComputedStyle, key, el)`. `sampleStylesScript()` returns the function handed to `page.evaluate`, composing them with the real `document` / `window.getComputedStyle`; it must be self-contained (Playwright serialises it) — no closures over module scope, the selector list is passed as the evaluate argument.
  - `export async function sampleComputedStyles(page)` resolves `samples[]`, or `[]` on error.
  - `export function aggregateSiteStyle(pageSamples)` (pure) returns `{ fonts, colors }`, split into `scoreColorRoles`, `collectFontRoles`, `parseFirstFontFamily`.
- `src/render/renderNavPages.js` — inside the desktop `captureViewport` visit, also `await sampleComputedStyles(page)` and collect `{ url, slug, samples }`; after the target loop write `computed-style.json` via `writeJson` (`src/images/manifest.js` L37-40) with `{ pages, site: aggregateSiteStyle(pages) }`. A failed page or an unavailable session simply has no `pages` entry; the file is still written (with `pages: []` and `{ fonts: [], colors: [] }`) so consumers can rely on its presence.
