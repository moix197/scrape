## Scope

Today `src/extract/structure.js` drops every `tel:` and `mailto:` anchor: `extractSectionLinks($, sectionEl, excludeAll)` (L283-298) has, at L291, `if (!href || href.startsWith('mailto:') || href.startsWith('tel:')) return;`. Phone numbers and email addresses therefore never reach `structure.json`, and downstream rebuilds lose the business's contact details.

After this card every section object produced by `buildSection` (L446-460) carries a new additive field:

```
contacts: [{ type: 'tel' | 'mailto', value, label }]
```

- `[]` when the section has no tel/mailto anchors.
- `value` normalisation:
  - `tel`: digits only, keeping a single leading `+` if the href had one. `tel:+1 (555) 010-2020` → `+15550102020`; `tel:5550102020` → `5550102020`.
  - `mailto`: the address lowercased, with any `?subject=...` (or any other `?` query) stripped. `mailto:Hello@Acme.com?subject=Hi` → `hello@acme.com`.
- `label` = the anchor's trimmed visible text, falling back to `value` when the text is empty.
- Dedupe **within a section** by `(type, value)`, first occurrence wins, document order preserved.
- `links` keeps excluding tel/mailto exactly as L291 does today — do not change that line's behaviour.
- Anchors inside a `<form>` remain excluded (the `excludeAll` list built in `extractSectionContent` L421-430 already contains form elements via `collectFormEls` L417-419).

Implementation (all in `src/extract/structure.js`, each function small and single-purpose):

- `classifyContactHref(href)` → `'tel' | 'mailto' | null`.
- `normalizeTelValue(href)` and `normalizeMailtoValue(href)` — tiny pure helpers implementing the rules above.
- `extractSectionContacts($, sectionEl, excludeAll)` placed next to `extractSectionLinks`, mirroring its `.find('a[href]').addBack('a[href]')` walk and its `isExcluded($, el, excludeAll)` (L158) check, deduping with a `Map` keyed `${type}:${value}` (same first-wins pattern as `collectSocialLinks` L539).
- Wire it into `extractSectionContent` (L421-430) so the object returned by `buildSection` gains `contacts` immediately after `links` in the object literal.

Fixture changes in `test/fixtures/structure.html`:

- In the contact section (L57-71) add `<a href="tel:+1 (555) 010-2020">Call us</a>` and a second mailto `<a href="mailto:Hello@Acme.com?subject=Hi">Email</a>` (which normalises to the same address as the existing `mailto:hello@acme.com` anchor and must collapse into it).
- In the footer (L109-114) add `<a href="tel:5550102020">555-010-2020</a>`.

- (b) the footer section's `contacts` deep-equals `[{ type: 'tel', value: '5550102020', label: '555-010-2020' }]`.

- (e) the existing socialLinks test (L136-143, "collects deduped socialLinks across sections, excluding mailto") and the form tests (L193, L205) pass unchanged.
