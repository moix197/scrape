## Scope

After C01-C03 every section in `structure.json` carries three new fields:

```
contacts:  [{ type: 'tel' | 'mailto', value, label }]
listItems: [{ ordered: boolean, items: string[] }]
form:      { fields: [{ label, type, required }] } | null
```

Two places rebuild sections from an **explicit field whitelist** and would silently drop them:
`pickSiteFooter` in `src/scrapeSite.js` (the site-level `footer`) and `mergeSections` in
`src/restructure.js` (what `pnpm restructure:apply` writes to `structure.restructured.json`).
This card extends both whitelists and adds the site-wide contacts hoist.

Observable after this lands, in `output/<domain>/`:

1. `structure.json` gains a top-level `contacts` array (verbatim shape):

```
structure.contacts: [{ type, value, label, where: { page, sectionOrder } }]
```

   - built from **every** section's `contacts` across **all** crawled pages, nav and footer
     sections included (i.e. read from `p.structure.sections` *before* `stripChromeSections`)
   - deduped by `(type, value)`; **first occurrence wins in crawl order**
   - `where.page` = that page's `url`; `where.sectionOrder` = that section's `order`
   - inserted in `buildStructureOutput`'s returned object immediately **after** `socialLinks`
2. `structure.json` top-level `footer` now also carries `contacts`, `listItems`, `form`.
3. `structure.restructured.json` (after `restructure:apply`) sections still carry
   `contacts`, `listItems`, `form`.

### Exact changes

**`src/scrapeSite.js`**

- `buildStructureOutput(pages)` (L277-292, currently not exported). Add a named `export` (no
  behaviour change) so it can be unit-tested. Add `contacts: collectSiteContacts(pages)` right
  after the `socialLinks` key.
- New small function `collectSiteContacts(pages)` (<= ~20 lines): same hoist pattern as
  `socialLinks` on L279 (`dedupeLinksByUrl(pages.flatMap(...))`). Use a `Map` keyed
  `${type}:${value}`, iterate pages then `page.structure.sections` in order, `set` only when
  the key is absent, return `[...map.values()]`. Each value is
  `{ type, value, label, where: { page: page.url, sectionOrder: section.order } }`.
  This mirrors `collectSocialLinks` (structure.js L539) and `dedupeLinksByUrl` (L231) — do not
  copy their bodies, do not generalise them; write one focused function.
- `pickSiteFooter` (L260-271). Its last two lines are the whitelist:
  `const { images, videos, headings, links, text } = footers[0];`
  `return { images, videos, headings, links, text };`
  Extend both to `{ images, videos, headings, links, text, contacts, listItems, form }`.

**`src/restructure.js`**

- `mergeSections(sections, sourceIds, entry, order)` (L109-128) rebuilds a merged section from
  an explicit list: `type, label, description (conditional), order, selectorPath (first source),
  images (flatMap + reindexed order), videos, headings, links (flatMap), text (join ' '),
  cards (flatMap, omitted when empty)`. Add, always present:
  - `contacts`: flatMap over sources, then dedupe by `(type, value)`, first wins
    (a tiny local helper `dedupeContacts(contacts)` — keep `mergeSections` under ~30 lines by
    extracting it)
  - `listItems`: flatMap over sources
  - `form`: first non-null `form` across sources in `sourceIds` order, else `null`
- `buildSectionSummaries` (L55-63, the LLM prompt input `{id,type,label,headings,text}`)
  stays **untouched** — the new fields must not reach the prompt.
- `restructureSite` already spreads `{ ...page, sections }` and `{ ...structureJson, pages }`,
  so page-level and top-level fields (incl. the new `contacts`) pass through `apply` with no
  change — do not add code for that.
