## Scope

Capture full-page screenshots of the home page and every page in the site `navTree`, always-on (no flag), using the shared browser session from C06. This gives the downstream rebuild real before/after material for the pitch.

Output written under `output/<domain>/` (verbatim shapes):

- `screenshots/<slug>-desktop.png` — viewport `{ width: 1440, height: 900 }`, `page.screenshot({ fullPage: true, type: 'png' })`.
- `screenshots/<slug>-mobile.png` — viewport `{ width: 390, height: 844 }`, `fullPage: true`.
- `screenshots/index.json` — array `[{ url, slug, desktop, mobile, capturedAt, error }]` where `desktop`/`mobile` are paths relative to `output/<domain>/` (e.g. `screenshots/home-desktop.png`), `capturedAt` is an ISO string, `error` is `null` on success or a string message. On failure `desktop`/`mobile` are `null` and no PNG is written for that target.

Slug rule: `'home'` for the root URL, otherwise the pathname's non-empty segments joined with `__` (`/services/weddings/` becomes `services__weddings`). This equals `derivePageName(url)` (scrapeSite.js L237-240) for single-segment paths and mirrors the downstream consumer's `home` / `__`-joined naming, which must stay compatible. Export `deriveScreenshotSlug(url)` from `src/render/renderNavPages.js`.

Targets: home (`cliOptions.rootUrl`) plus every `url` in the site nav tree (`buildStructureOutput(...).nav?.navTree`, walked recursively through `children`), same-origin only, deduped by URL, restricted to URLs present in `crawlResult.pages` (already robots-checked and rate-limited during the crawl); home first. Deep/non-nav pages keep today's plain-fetch/fallback behaviour and are never rendered here.

Guardrails: each viewport capture calls `await rateLimiter.throttle()` first and is logged through `onFetchLogged({ url, status: 200 | 0, timestamp: new Date().toISOString(), method: 'screenshot' })` (`status: 0` on failure), so it lands in `fetch-log.jsonl` like every other network hit.

Degrade: when `session.available === false` or a `session.withPage` call resolves `null`, write an index entry with `error` (`'playwright unavailable'` / `'render failed'`), continue with the next target, never throw; `runScrape` exit code stays 0.

Implementation in `src/render/renderNavPages.js`:

- `export function deriveScreenshotSlug(url)` — pure.
- `export function buildRenderTargets({ rootUrl, navTree, crawledUrls })` — pure, returns `[{ url, slug }]` (home first, deduped, same-origin, only URLs in `crawledUrls`, walks nested `children`).
- `export async function renderNavPages({ session, targets, outputBase, onFetchLogged, rateLimiter })` — for each target captures desktop then mobile, writes PNGs, writes `screenshots/index.json` with `writeJson` from `src/images/manifest.js` (L37-40), returns the index array.
- Split into `captureViewport(session, target, viewport, outputBase)` (throttle, `withPage`, `page.screenshot`, write PNG, return relative path or `null`) and `buildIndexEntry(target, results)`.
- PNG writing: `fs.mkdir(path.join(outputBase, 'screenshots'), { recursive: true })` + `fs.writeFile`. Mirror `saveImageBuffer` (scrapeSite.js L40-46) — it is `images/`-specific and not exported; a 6-line sibling `saveScreenshotBuffer` here is acceptable. Do not generalise it speculatively.

Hook in `src/scrapeSite.js` `runScrape` (L334): after `buildStructureOutput` and before `writeAllOutputs` (L323), build targets with `buildRenderTargets({ rootUrl: cliOptions.rootUrl, navTree: structureOutput.nav?.navTree ?? [], crawledUrls: crawlResult.pages.map((p) => p.url) })`, then `await renderNavPages({ session: browserSession, targets, outputBase, onFetchLogged: (entry) => fetchLog.push(entry), rateLimiter: createRateLimiter(cliOptions.rate) })` (import `createRateLimiter` from `src/utils/rateLimiter.js`; `cliOptions.rate` defaults to 1). Because `writeFetchLog` runs last inside `writeAllOutputs` (L331), the screenshot entries end up in `fetch-log.jsonl`. Print `Screenshots: <n> captured, <m> failed` to the console alongside the existing progress lines.
